# forio-skills — маркетплейс навыков Claude Code

Личный каталог плагинов и навыков (skills) для [Claude Code](https://code.claude.com).
Один раз подключаешь маркетплейс — и ставишь из него навыки в **любой** свой
проект. Пополняется по мере создания новых навыков.

## Установка (для пользователя)

```text
/plugin marketplace add Forio224/claude-skills
/plugin install web-design@forio-skills
/plugin install tutor@forio-skills
```

Первая команда регистрирует маркетплейс, остальные ставят плагины. После
установки навыки доступны во всех проектах.

## Обновление

Навыки правятся здесь → `git push`. У пользователя новая версия прилетает после:

```text
/plugin marketplace update
```

> В `plugin.json` намеренно **не указан `version`** — значит каждый коммит в
> этот репозиторий считается новой версией, и `/plugin marketplace update`
> подтягивает последнее состояние. Если для какого-то плагина захочется
> контролируемых релизов (обновление только по явному бампу) — добавь в его
> `plugin.json` поле `"version": "x.y.z"` и повышай его на каждый релиз.

## Как устроен репозиторий

```
.claude-plugin/
  marketplace.json          # каталог: список всех плагинов и где их искать
plugins/
  web-design/               # плагин
    .claude-plugin/
      plugin.json           # манифест плагина
    skills/
      multivariant-web-design/
        SKILL.md            # сам навык (+ PLAN/DESIGN/BASELINE/references)
  tutor/                    # плагин
    .claude-plugin/
      plugin.json
    skills/
      tutor/
        SKILL.md
        references/topic.md   # режим «Тема»
    hooks/
      hooks.json            # зеркало урока в Obsidian
      lesson-log.mjs
```

- `marketplace.json` — витрина. Поле `metadata.pluginRoot: "./plugins"`
  позволяет писать в `source` короткое имя папки плагина.
- Один плагин может нести несколько навыков (`skills/<name>/`), а также агентов,
  хуки и MCP-серверы.

## Каталог плагинов

| Плагин | Навыки | За что отвечает |
|--------|--------|-----------------|
| [`web-design`](./plugins/web-design/) | `multivariant-web-design` | Дизайн веб-страниц и интерфейсов в трёх заметно разных вариантах (A продуктовый / B живой / C характерный) для живого сравнения. |
| [`tutor`](./plugins/tutor/) | `tutor` | Наставник: задачи уровнями подсказок без готового решения и уроки по теме с зеркалом в Obsidian. |

### web-design → multivariant-web-design

На любую визуальную задачу (лендинг, страница, экран, форма, дашборд,
UI-компонент) собирает **три отдельных, ощутимо разных варианта дизайна** — не
один макет в трёх цветах:

- **A. Продуктовый** — выверенная сетка, строгая иерархия, спокойная типографика
  (в духе refero).
- **B. Живой** — анимация, движение, интерактивные фоны (в духе reactbits).
- **C. Характерный** — свечения, градиентные бордеры, выразительные детали
  (в духе uiverse).

Выход — папка `design-variants/` с `index.html`-переключателем и тремя файлами
вариантов. Чужой стиль не воспроизводится по памяти — источник подтягивается
реально (каталог источников в `references/sources.md`).

### tutor → tutor

Режим наставника для учёбы. Два режима, выбираются по запросу.

**Задача** — LeetCode, учебный проект. Срабатывает на «объясни», «почему ошибка»,
«проверь мой код», «не давай решение», `/tutor`.

- **Решение за человека не пишется** — ни целиком, ни наброском. Механику языка
  (срезы, что возвращает метод) объясняет прямо, но на посторонних примерах.
- **Ошибки называются все сразу**, включая скрытые и логические, которые не
  падают, — с причиной, а не симптомом, и с порядком починки.
- **Проверка готового кода** — таблица краевых случаев как доказательство
  корректности, прямой вердикт, места «правильно случайно», стиль, сложность.
- **Тип ошибки** — описка, дыра в предпосылке или неверное представление;
  от типа зависит ответ.

**Тема** — `/tutor тема: …`, «научи», «хочу разобраться в». Построен на системе
[amosblomqvist/learn](https://github.com/amosblomqvist/learn) из видео
«How I Use AI to Learn Things».

- **Разведка → план → урок.** Двоичный поиск границы знаний, карта зависимостей
  на mermaid и стоп до «ок», затем цикл по узлам: мотивировать → утвердить →
  связать → проверить тестом.
- **Сначала безусловные истины, потом «как я мог бы додуматься сам».**
- **Тесты** — через `AskUserQuestion`, варианты строятся из реальных заблуждений.
- **Зеркало в Obsidian.** Хуки плагина дописывают весь урок (реплики, объяснения,
  тесты и ответы) в заметку с `тип: урок` в папке из `~/.claude/tutor.json`:

  ```json
  { "lessons": "D:/da/Obsidian/Учёба" }
  ```

  Нужен Node.js 20+. Ошибки хуков пишутся в `~/.claude/tutor-state/errors.log`.
  Тесты: `node --test "plugins/tutor/hooks/*.test.mjs"`.

## Как добавить новый плагин/навык

1. Создай `plugins/<плагин>/.claude-plugin/plugin.json` (минимум — `name`).
2. Положи навык в `plugins/<плагин>/skills/<навык>/SKILL.md`.
3. Допиши плагин в массив `plugins` в `.claude-plugin/marketplace.json` и строку
   в таблицу выше.
4. `git push`. Пользователи: `/plugin marketplace update`, затем
   `/plugin install <плагин>@forio-skills`.
